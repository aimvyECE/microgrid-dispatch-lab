# Microgrid Dispatch Lab

**Research prototype · synthetic data · not a production energy-management system**

A small, reproducible Python experiment for comparing grid-only, photovoltaic and battery-assisted electricity dispatch. It makes the equations and assumptions visible instead of presenting unexplained savings estimates.

## Why this exists

A decision about storage depends on time-varying demand, tariffs, electricity carbon intensity and losses. This prototype asks: **under a known illustrative daily profile, how would a cost-minimizing battery operate, and what changes if operational emissions receive an explicit monetary weight?** It does not answer whether a real installation is economically viable.

## Quick start

Python 3.10+ recommended. From this directory:

```sh
python -m venv .venv
# Activate the environment using the command appropriate to your operating system.
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python microgrid.py --output results
```

The CLI writes `summary.json` (metrics and dispatch) and `dispatch.csv` (auditable time steps). It does not access a network, an account, an API or a real energy device. An example output is committed in `examples/synthetic_day/`.

## Parameter sensitivity, with auditable baselines

```sh
python sensitivity.py --output results/sensitivity
```

Explore capacity (0/5/10 kWh), power (2/4 kW), one-way efficiency (0.90/0.95)
and carbon valuation (0/0.20 EUR per kgCO₂e) in **24 synthetic cases**. Exports
include exact inputs, solver-library versions and matching no-storage baselines.
The sweep starts and ends at zero SOC, so its results are intentionally not
identical to the original half-full-battery example. See
[the experiment guide](docs/EXPERIMENTS.md) and [committed sample CSV](examples/sensitivity/sensitivity.csv).

This is operational sensitivity, not investment sizing. No payback or real-world
savings forecast is inferred from the synthetic day.

## Forecast-signal regret: stress-test the optimizer's assumptions

```sh
python forecast_regret.py --output results/forecast_regret.json
```

A schedule that looks optimal under announced tariffs need not perform well
when those signals change. This experiment fixes demand/PV (still perfectly
known), optimizes against forecast price/carbon signals, then **scores that same
feasible schedule using realized signals**. It reports objective regret against
a hindsight lower bound and savings or losses against no storage. Both scores
include the identical throughput proxy and carbon valuation.

Four deterministic synthetic stress cases include a peak shifted four hours
early/late. In the committed example the late peak forecast loses about
**EUR 0.704 of objective value** against hindsight. The other three cases tie
within numerical precision: inaccurate signals do not necessarily alter a
schedule. These are scenario outcomes, NOT probabilities, expected monthly
benefit or real-world savings. A constructed test shows a wrong tariff can
make storage worse than no storage.

The output retains exact inputs, forecasts, both dispatches and dependency
versions. This deliberately isolates **price/carbon information risk**; it is
not rolling-horizon control, stochastic optimization, or a repair method for
load/PV forecast errors. Initial and final storage remain zero in this example.

## Model

For each interval t, all flows below are **energy in kWh**, not power:

- `grid + PV + discharge = load + charge + curtailment`
- `SOC[t] = SOC[t-1] + eta × charge − discharge / eta`
- `0 ≤ charge, discharge ≤ battery_power_kW × interval_hours`
- `0 ≤ SOC ≤ battery_capacity_kWh`
- Final SOC equals initial SOC. The model cannot obtain free energy by emptying the battery at the horizon boundary.

The objective is:

`Σ grid × (price + carbon_price × grid_intensity) + throughput_penalty × (charge + discharge)`

Prices are EUR/kWh; intensity is kgCO₂e/kWh; the carbon valuation is EUR/kgCO₂e. The default 0.95 efficiency is **one-way**, giving 90.25% round-trip efficiency. Grid charging is permitted. Grid exports are not permitted; excess solar can be curtailed. The throughput penalty is only an illustrative degradation proxy, not a calibrated battery lifetime model.

The formulation is a linear program solved by SciPy's HiGHS backend. It does not include a binary constraint forbidding simultaneous charging and discharging. Positive throughput costs, nonnegative energy/carbon prices and free PV curtailment discourage cycling under the supported assumptions; do not extend to negative prices or export incentives without revisiting this relaxation.

## Illustrative result

The default input is generated by simple formulas in `synthetic_day()`. **It is not a real French consumption curve, tariff or emissions dataset.** It represents a single invented 24-hour horizon with 1-hour intervals.

| Scenario | Grid energy bill | Operational grid emissions |
|---|---:|---:|
| Grid only | €9.26 | 7.64 kgCO₂e |
| Solar only | €6.31 | 5.54 kgCO₂e |
| Solar + battery, cost objective | €3.07 | 2.28 kgCO₂e |
| Solar + battery, carbon valuation | €3.07 | 2.28 kgCO₂e |

These bill values exclude the throughput proxy, capital costs, taxes and fixed network charges. Full optimization-objective values are in the JSON. The carbon-valued and cost-only schedules happen to agree for this invented profile: this is **not evidence that the objectives always align**. Tests include a constructed case where they differ.

## Limitations that matter

- Single electrical bus; demand/PV have perfect foresight. Signal-only forecast stress is available separately; no demand/PV forecast error or network physics.
- No grid import limit, outage model, reserves, thermal constraints or AC power-flow study.
- No battery investment optimization, aging calibration, tariff subscriptions or seasonal analysis.
- Operational grid emissions only: no lifecycle embodied carbon, marginal emissions estimation or avoided-emissions claim.
- Synthetic profiles cannot establish real savings, payback, installation sizing, regulatory compliance or client outcomes.
- Never connect this educational code directly to a live controller.

## Reproducibility and provenance

This initial prototype was developed with AI assistance. It has not been deployed for a client, independently reviewed or validated against metered data. There is no claim of historical adoption or previous contributions. Dependencies are NumPy and SciPy; no third-party source code or model weights were copied into this repository.

The initial published version passed [GitHub Actions](https://github.com/aimvyECE/microgrid-dispatch-lab/actions/runs/43315182391). The workflow tests Python 3.10 and 3.12; check the latest run for the current revision. Users should also reproduce tests in their own environment.
